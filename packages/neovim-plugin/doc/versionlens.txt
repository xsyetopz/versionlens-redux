INTRODUCTION                                                   *versionlens-intro*

VersionLens Redux displays dependency diagnostics and code lenses from the
shared Rust `versionlens-lsp` server in supported manifest files.

Requirements:

- Neovim 0.10 or newer.
- `versionlens-lsp`: bundled with a release archive, selected through
  $VERSIONLENS_LSP, supplied with `cmd`, installed on $PATH, or downloaded
  automatically (see |versionlens-download|).

==============================================================================
INSTALLATION                                                 *versionlens-install*

Download the release archive for the current platform and architecture, then
extract it under a Neovim package directory such as:

  $XDG_DATA_HOME/nvim/site/pack/versionlens/start/versionlens-redux

The archive contains this plugin plus its matching language-server binary.
For monorepo development, add packages/neovim-plugin to 'runtimepath'.

==============================================================================
SETUP                                                           *versionlens-setup*

The plugin starts automatically with defaults. Plugin managers may call:

>lua
    require("versionlens").setup({})
<

Calling setup multiple times is safe. Set `g:versionlens_disable_auto_setup`
to 1 before loading the plugin when setup must be entirely manager-controlled.

==============================================================================
COMMANDS                                                     *versionlens-commands*

:VersionLensStart                                           *:VersionLensStart*
    Start or attach VersionLens Redux to the current buffer.

:VersionLensStop                                             *:VersionLensStop*
    Stop VersionLens Redux clients attached to the current buffer.

:VersionLensRestart                                       *:VersionLensRestart*
    Restart VersionLens Redux for the current buffer.

:VersionLensRefresh                                       *:VersionLensRefresh*
    Refresh visible VersionLens code lenses.

:VersionLensInfo                                             *:VersionLensInfo*
    Show the selected language-server executable.

CONFIGURATION                                                   *versionlens-config*

>lua
    require("versionlens").setup({
      auto_download = true,
      autostart = true,
      cmd = nil,
      codelens = {
        enabled = true,
        events = { "BufEnter", "InsertLeave" },
      },
      keymaps = {
        refresh = nil,
        restart = nil,
      },
      notify = true,
      on_attach = nil,
      root_dir = nil,
      settings = {},
      root_markers = {
        ".git",
        ".nvmrc",
        ".node-version",
        ".bun-version",
        "Cargo.toml",
        "package.json",
        "pnpm-workspace.yaml",
        "pyproject.toml",
        "go.mod",
        "rust-toolchain",
        "rust-toolchain.toml",
      },
    })
<

`cmd` accepts an executable string or argv-style list. Resolution order:
`cmd`, $VERSIONLENS_LSP, bundled platform binary, repository debug binary,
previously downloaded binary, then `versionlens-lsp` on $PATH.

`settings` is the `versionlens` configuration section. It is sent to the server
in `vim.lsp.start` and returned for the server's `workspace/configuration`
requests, so Neovim answers them without extra handlers. Empty tables are sent
as JSON objects (the server rejects arrays). For example:

>lua
    require("versionlens").setup({ settings = { ... } })
<

See the VersionLens settings reference for the available keys.

                                                             *versionlens-download*
`auto_download` (default true) downloads the server when no other step finds
one. It fetches the release asset `versionlens-lsp-<version>-<target>` (tar.gz,
zip on Windows) and `SHA256SUMS` for the plugin's version from GitHub with
`curl`, verifies the archive with `sha256sum`, `shasum`, or `certutil`
(whichever exists), extracts it with `tar` (Windows: System32\tar.exe), and installs it into
stdpath("data")/versionlens/<version>/. Other version directories there are
removed. Alpine (musl) systems get the musl build. A failed download is not
retried until |:VersionLensStart| or |:VersionLensRestart|. Buffers opened
while downloading start once it finishes. On a checksum mismatch the download is deleted, the server is not
started, and the error names the expected and actual sums. With
`auto_download = false` no network request is made and an error explains how
to install the server.

HEALTH                                                         *versionlens-health*

Run `:checkhealth versionlens` to verify Neovim and language-server discovery.
The report shows which resolution step found the server.
