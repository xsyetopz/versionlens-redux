1. INTRODUCTION                                            *versionlens-intro*

VersionLens starts the `versionlens-lsp` language server on each manifest the
server reads (package.json, Cargo.toml, requirements.txt, go.mod, and more)
and shows the latest versions as code lenses, inlay hints, and diagnostics.
Code actions and code lenses update a dependency.

The plugin asks the server for the files it reads with
`versionlens-lsp --file-types`, so new server file types need no plugin
change.

==============================================================================
2. SERVER                                                 *versionlens-server*

The first server found is used:

  1. The `cmd` option.
  2. `$VERSIONLENS_LSP`.
  3. `bin/versionlens-lsp` on 'runtimepath' (the release archive).
  4. `versionlens-lsp` on `PATH`.
  5. A previous download in `stdpath("data")/versionlens/<version>/`.

When none is found and `auto_download` is true, the matching release is
downloaded with curl, checked against the release SHA256SUMS, and installed in
that data directory. Failures are reported with |vim.notify()|.

3. SETUP                                                   *versionlens-setup*

                                                         *versionlens.setup()*
The plugin calls `setup()` when it loads, unless
`vim.g.versionlens_disable_auto_setup` is set. Options and defaults: >lua

  require("versionlens").setup({
    cmd = nil,
    auto_download = true,
    autostart = true,
    codelens = true,
    inlay_hints = true,
    ascii = false,
    glyphs = {},
    winbar = false,
    settings = {},
    on_attach = nil,
  })
<
`ascii`       Use ASCII instead of Unicode glyphs in the status component and
              in lenses and hints: `ok`, `^`, `~`, `-`, `x`, `!` for the
              Unicode `✓`, `↑`, `◐`, `○`, `✗`, `⚠` that stand in for the
              VS Code emoji. `settings.indicators` overrides single ones.
`glyphs`      Override single glyphs by name (see |versionlens-status|).
`winbar`      Set each manifest window's 'winbar' to the status component
              when it is empty.

                                                       *versionlens-settings*
`settings` holds the server settings, the VS Code `versionlens.*` keys
without the prefix. Unknown keys and wrong types are reported at `setup()`.

  Booleans     `enabled`, `codeLens`, `inlayHints`, `prereleases`,
               `vulnerabilities`, `strictSsl`, `stats` (a summary lens
               above each manifest)
  Numbers      `timeoutMs`, `concurrency`, `cacheMinutes`
  Strings      `githubToken`, `updateSeverity` (`off`, `hint`, `info`,
               `warning`, or `error`: the diagnostic each outdated
               dependency gets; default `info`)
  Lists        `prereleaseTags` (only prereleases with one of these tags),
               `fileTypes` (only these file type or registry ids),
               `workspaceExclude` (globs a workspace update skips)
  Maps         `registries` (registry id to URL template, for mirrors),
               `authorization` (URL prefix to Authorization header),
               `install` (file type or registry id to shell command, run
               when a save changes the dependencies),
               `files` (extra glob to file type id),
               `indicators` (glyph per state: `latest`, `update`,
               `checking`, `failed`, `unreadable`, `vulnerable`, `newer`,
               `satisfies`, `noMatch`, `directory`, `build`, `yanked`,
               `deprecated`),
               `providers` (registry id to a table of `cacheMinutes`,
               `strictSsl`, `prereleaseTags` that override the global
               value for that registry)

Example: >lua

  require("versionlens").setup({
    settings = {
      prereleases = false,
      timeoutMs = 10000,
      registries = { npm = "https://npm.example.com/{name}" },
      authorization = { ["https://npm.example.com/"] = "Bearer TOKEN" },
      install = { npm = "bun install" },
      files = { ["deps/*.list"] = "requirements" },
    },
  })
<
Calling `setup()` again sends the new settings to running servers, with no
restart.

4. COMMANDS                                             *versionlens-commands*

                                                                *:VersionLens*
:VersionLens
    Open a |vim.ui.select()| menu of what applies to the current buffer,
    from its status: hide or show versions and prereleases, update at each
    level while dependencies are outdated, sort, install, refresh, update the
    workspace, clear the cache, log, restart, info, and url authentication.

:VersionLens {subcommand} [{argument}]
    All subcommands complete with <Tab>.

  show, hide, toggle                Show or hide versions in the buffer.
  prereleases [show|hide|toggle]    Prerelease versions; default toggle.
  update [latest|major|minor|patch] Update every dependency in the buffer.
  workspace [level]                 Update every manifest in the workspace.
  sort                              Sort the manifest's dependencies.
  install                           Run the manifest's install command.
  refresh                           Fetch the buffer's versions again.
  clear-cache                       Drop cached registry answers.
  log                               Show the server's log messages.
  restart                           Restart the server.
  info                              Show the server command and status.
  auth [add|remove]                 Store or forget an Authorization header
                                    for a registry URL prefix; default add.
                                    Headers are kept in
                                    stdpath("data")/versionlens/authorization.json,
                                    readable only by you (mode 0600), and
                                    replace an `authorization` setting for the
                                    same prefix.

`updateAll`, `clearCache`, and `output` are accepted as aliases of `update`,
`clear-cache`, and `log`.

5. STATUS                                                  *versionlens-status*

The server sends `versionlens/status` for each open manifest. The plugin keeps
the latest one per buffer; |versionlens.statusline()| renders it: >lua

  require("versionlens").statusline()
<
For lualine: `lualine_x = { require("versionlens").statusline }`. For the
built-in line: >vim

  set statusline+=%{%v:lua.require'versionlens'.statusline()%}
  set winbar=%{%v:lua.require'versionlens'.statusline()%}
<
or set `winbar = true` in |versionlens.setup()|.

  Unicode  ASCII  Meaning
  ◉        VL     versions shown
  ◌        vl-    versions hidden
  ⠋ ...    | / -  working (spinner)
  ↑N       ^N     N dependencies outdated
  ✗N       xN     N lookups failed
  ⚠N       !N     N vulnerable
  ✓        ok     all up to date
  β        pre    prereleases on

Override a glyph with `glyphs = { outdated = "U" }`. Names: `shown`, `hidden`,
`ok`, `outdated`, `failed`, `vulnerable`, `prereleases`, `spinner` (list).
